## Затверджена модель дублювання

Scaler має створювати в тій самій кампанії:

- новий AdSet;
- нове Page Video;
- новий Creative через `object_story_spec.video_data`;
- нове оголошення у новому AdSet;
- без передачі `object_story_id` існуючої публікації;
- у статусі `PAUSED` під час тестів.

Справжню нову копію підтверджує одночасне виконання умов:

- `new_ad_id != source_ad_id`;
- `new_creative_id != source_creative_id`;
- `copied_adset_id != source_adset_id`;
- нове оголошення належить новому AdSet;
- нове оголошення використовує новий Creative;
- Creative створений через `object_story_spec`, а не `object_story_id`;
- новий Creative використовує новий `video_id`;
- у Ads Manager вибрано «Створити оголошення», а не «Використовувати існуючу публікацію».

## Результати тестів

### v26.3 — відхилено

- Новий AdSet було створено.
- Creative створювався через `object_story_id`.
- Ads Manager показував «Використовувати існуючу публікацію».
- Такий спосіб не відповідає задачі дублювання оголошення.

### v26.4 — структура нового дубля підтверджена

Джерело:

- AdSet: `120247989505660301`
- Ad: `120247989505540301`
- Creative: `1785909172594984`
- root video: `2189511635226791`

Створено:

- AdSet: `120248233771070301`
- Ad: `120248233772070301`
- Creative: `1471180001441578`
- Page Video: `1848696159451925`

Підтверджено:

- усі структурні ID нові;
- новий Ad знаходиться у новому AdSet;
- новий Ad використовує новий Creative;
- Creative створено через `object_story_spec.video_data`;
- `object_story_id` існуючої публікації у запит Creative не передавався;
- текст, CTA, URL і Pixel збігаються;
- Ads Manager показує «Створити оголошення»;
- оголошення створено без API-помилки.

Важливо: загальний `true_duplicate_ok` у звіті v26.4 дорівнює `false`, бо API-аудит знайшов одну розбіжність AdSet:

- у джерелі `targeting_automation.individual_setting` містить `age: 1` і `gender: 1`;
- у копії це вкладене поле відсутнє;
- явні `age_min`, `age_max`, гео, плейсменти та платформи у звіті збережені.

Поки не доведено, чи це лише нормалізація/read-only поведінка Meta, чи фактична зміна налаштування. Тому v26.4 підтверджує нову структуру Ad + Creative + AdSet, але ще не закриває повну fidelity-перевірку AdSet для production.

### v26.5 — підготовлено до тесту

Єдина цільова зміна відносно v26.4:

- не завантажувати preferred thumbnail;
- не передавати `image_url` або `image_hash` у `object_story_spec.video_data`;
- залишити вибір мініатюри Meta у режимі `AUTO`.

Логіка нового AdSet, нового Page Video, нового Creative через `object_story_spec` і нового Ad не змінювалася.

## Поточний наступний крок

1. Запустити `fb_duplicate_test.py` v26.5 для тестового AdSet `120247989505660301`.
2. Перевірити в Ads Manager:
   - режим оголошення — «Створити оголошення»;
   - мініатюра — `Авто`;
   - текст, CTA, URL, Pixel і статус оголошення;
   - налаштування віку та статі у новому AdSet.
3. Перевірити JSON-звіт v26.5, особливо `adset_differences`.
4. Не переходити до production `fb_scaler.py`, доки не закрито fidelity AdSet або не доведено, що розбіжність є лише нормалізацією API.
